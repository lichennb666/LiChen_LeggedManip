# VBC 交接文档：环境几何修复 + 臂 IK 升级（2026-09-25）

> 面向：换一台电脑接手 `LeggedManip_Lab` 的同学。
> 本文记录**为什么之前"怎么训都训不出来"**、这一轮**改了什么**、**怎么验证**、**怎么继续训练**。

---

## 0. 一句话总结

之前的失败**不是训练方法/超参的问题**，而是三个环境层面的硬伤叠加：

1. **机器人底盘每次 reset 被随机丢在 ±0.5m、随机朝向** → 约 **40% 的物体从站立位姿根本够不到**；
2. **物体生成在 x=0.62**，正好卡在底层 WBC 训练的末端工作区间 `x∈[0.35,0.65]` 的**最外端** → 手臂要伸到关节极限（`joint2≈2.9 / joint3≈-2.8`），动力学上控不住；
3. **臂的 IK 用的是 IsaacLab 内置单步微分 IK（局部算法）** → 连续目标下 **~6cm 误差**，手对不准。

本轮把这三条都修了并逐条验证：

| 指标 | 修之前 | 修之后 |
|---|---|---|
| 物体在臂可达范围内的比例 | ~60% | **100%** |
| 臂 IK 位置残差（可达目标） | ~60 mm | **0.0 mm** |
| 物体到臂基座距离 | 0.23 ~ 1.22 m | **0.54 ~ 0.73 m（工作中心）** |
| 物体方向（link0 系） | 乱（可能在身后） | **正前方 `[0.97, 0.00, 0.23]`** |

## 1. 背景问题（修之前的状态）

- 训练 VBC teacher，成功率长期卡在很低水平（最好一版 ~1750 轮才见到 ~22% grasp，单环境成功率极低），**换个超参就退化**。
- 现象：`lift` 平台期只有 2~4cm（成功阈值 10cm），`grasp` 事件稀疏。
- 本轮做了**不训练的决定性诊断**（脚本化抓取 + 可达率统计），定位到上面三条根因。

## 2. 本轮具体修改

### 批次① 任务几何（只改配置）

文件：`source/LeggedManip_Lab/LeggedManip_Lab/tasks/manager_based/leggedmanip_lab/config/go2_piper/vbc_env_cfg.py`

| # | 位置 | 改动 | 原因 |
|---|---|---|---|
| 1 | `Go2PiperVBCTeacherEnvCfg.__post_init__` | `events.reset_base.params["pose_range"]` 改为 `x/y ±0.05、z ±0.02、roll/pitch ±0.02、yaw ±0.10`（原来继承 locomotion 的 `x/y ±0.5、yaw ±π`） | 底盘乱丢导致物体一半够不到；与配置里 "stage-1 物体在臂可达范围内" 的设计注释矛盾 |
| 2 | `_velocity_scale_from_env()` 默认值 | `"0.4,0.3,0.5"` → **`"0,0,0"`** | 阶段一冻底盘（3 个底盘动作维失效），专心学抓；阶段二用环境变量 `VBC_VELOCITY_SCALE` 解冻，代码无需改 |
| 3 | `VBCEventCfg.reset_cube` / `VBCMultiObjectEventCfg.reset_cube` | 物体 `pose_range` 的 `x/y ±0.12` → **`±0.06`** | 课程从最容易的位置起步，之后由 `VBCCurriculumCfg.cube_position_range` 自动扩到 ±0.30 |
| 4 | 物体/桌子 `init_state` | `x=0.62` → **`x=0.50`**（`_vbc_multi_object_cfg`、`VBCSceneCfg.table`、`VBCSceneCfg.cube` 三处） | 0.62 在 WBC 训练范围 `x∈[0.35,0.65]` 最外端；0.50 与动作里的 `pose_anchor.x=0.50` 一致，是工作中心 |

### 批次② 臂 IK 升级（新增/修改代码）

**新增** `mdp/piper_ik_torch.py`：torch 批量版 Piper 运动学 + 阻尼最小二乘（DLS）IK。
- 与 ROS 侧 `piper_kinematics.py` 同一条链；已验证 **FK 与 numpy 参考最大差 3e-8 m**。
- 支持**位置**或**位置+朝向**联合求解，可在 4096 并行环境上按步迭代到收敛。

**修改** `mdp/vbc_actions.py`：
- `import PiperKinematicsTorch`；
- `__init__`：新增 `self._arm_joint_ids` 与 `self._piper_kin`，并支持 `arm_ik_backend` 选择后端（`"piper_torch"` 默认 / `"isaaclab"` 回退到内置 IK）；
- `apply_actions`：用新 IK 求解，**以 `default_joint_pos`（home 位姿）为初值**（离线验证：从 home 解到任意可达桌面目标 = 0mm；用当前位姿热启动会掉进别的局部解，残差 80~225mm）；
- 新增 `_ee_command_pose_link0()`：把 `_processed_pose_command`（xy 在 link0 系、z 在世界系、四元数相对 link0）换算成 **link0 系**的位置+四元数目标；
- 新增配置项（默认值）：
  - `arm_ik_backend = "piper_torch"`
  - `arm_ik_iterations = 10`
  - `arm_ik_damping = 1.0e-4`
  - `arm_ik_step_clip = 0.40`  ← **关键**：太小（0.15）会走不到目标
  - `arm_ik_orientation_weight = 0.05`

> 注意：`arm_ik_command_type` 目前仍是 **`"position"`**（只控位置）。要启用朝向控制改成 `"pose"`（需先用示教/先验确定默认抓取朝向，否则臂会扭）。

### 新增的诊断脚本

| 脚本 | 用途 |
|---|---|
| `scripts/rsl_rl/vbc_reach_diag.py` | reset 后统计"物体在臂可达范围内的比例"（多初值 IK 参考） |
| `scripts/rsl_rl/vbc_ik_env_check.py` | 用环境真实的 reset 初值 / 物体目标检查 torch IK |
| `scripts/rsl_rl/vbc_grasp_test.py` | 脚本化抓取（到上方→下降→闭合→抬起）；已加**底盘锁定**、IK/PD 诊断、锁定抓取点 |
| `scripts/rsl_rl/vbc_grasp_hold_test.py` | 固定（多初值解析）IK 解 + 底盘瞬移到可达位置的夹持测试 |
| `scripts/rsl_rl/piper_kinematics.py` | 从 ROS 包拷贝的 numpy 参考实现（供脚本比对） |

## 5. 已知问题 / 后续待办

1. **臂 PD 跟踪偏慢**（最弱环节）
   - IK 已准到 0.0mm，但手臂要 ~1.5s 才跟到新构型。URDF 限制：joint1/2 20 N·m、joint3 15、joint4 7、joint5/6 5；速度 3 rad/s。
   - 可选：提高臂刚度/阻尼；或加力矩补偿；或让策略学会"到位后再等一会"。
   - 若训练中 `object_reach_linear` 长期不抬头，优先处理这条。

2. **朝向控制未启用**
   - 现在是 `arm_ik_command_type="position"`，只控位置。
   - 策略的动作里其实**有 3 维 wrist 朝向**且观测里有物体朝向/形状 → 改成 `"pose"` 后**"不同物体不同抓法"才有通道**。开启前需确定默认抓取朝向。

3. **底盘速度死区**（阶段二前提）
   - 底层 WBC 训练命令范围实际是 `x ±1.0 / y ±0.6 / wz ±1.0`（`curriculum_enabled=false` 会强制用 `limit_ranges`）；
   - 死区来自**奖励**：`track_lin_vel_xy_exp.deadband=0.05`、`rel_standing_envs=0.1`、低速奖励阈值 0.2 → 命令接近 0 时策略学会"不动"。
   - 解决：高层面加"位置闭环"（策略给位移，反馈算速度），或重训底层时去掉/调小这些奖励项。

4. **阶段二课程**：把批次①第 1 条的 `reset_base` 范围随成功率**从 ±0.05 逐步扩到 ±1.0m、yaw 到 ±π**，并配合 `VBC_VELOCITY_SCALE` 解冻。

## 6. 关键坐标/常量备忘（排查用）

- Piper 链 FK 基准系 = **`link0`**；`piper_tcp_position(q)` 与仿真 `end_effector` 在 link0 系位置一致（差 0.0mm）。
- 臂关节顺序 `joint1..joint6`（IsaacLab importer，本次已用 `find_joints(..., preserve_order=True)`，无顺序问题）。
- `pose_anchor=(0.50,0.00,0.55)`、`position_scale=(0.02,0.02,0.02)`、`orientation_scale=(0.05,0.05,0.08)`。
- 冻结 WBC 训练时末端工作区间：`x∈[0.35,0.65]、y∈[-0.2,0.2]、z∈[0.4,0.7]`（物体应放中心，故 x=0.50）。
- 夹爪：`joint7/joint8`（prismatic，镜像开合），open `(0.04,-0.04)`、close `(0.002,-0.002)`。

## 7. 环境注意事项

- ROS 侧用系统 python；训练用 conda 环境 **`leggedmanip`**。
- 代理 `127.0.0.1:7890` 会劫持 Isaac 资产下载；`leggedmanip` 环境已加钩子只对 Isaac 域名豁免。
- 训练运行时配置 dump 在 `<run>/params/env.yaml`，是确认改动是否生效的权威依据。
- 一个 4096 训练约占 7~12GB 显存；并发两个会显著变慢且可能 OOM。
